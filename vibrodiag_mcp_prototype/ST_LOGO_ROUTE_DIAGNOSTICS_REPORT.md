# ST logo, no-gradient, and model-route diagnostics cleanup

## Scope

This patch only changes the webchat UI and its diagnostics text. It does not modify logger, acquisition, SDK decoding, PSD, variance, filters, or impact ring-down code.

## UI changes

- Added a stable `/assets/st-logo.png` route while keeping the old `/assets/st_logo_2020.png` route for compatibility.
- Updated the main webchat, live graph, and direct NPU chat headers to use `/assets/st-logo.png`.
- Increased the logo display area so the logo is visible as a real logo rather than a tiny mark.
- Confirmed that the webchat templates contain no `linear-gradient` styling and no magenta/purple gradient accent line.

## Diagnostics clarification

The text `run_autonomous_sensor_check (deterministic_router)` was misleading because it described only the route used to select the MCP tool, not necessarily the source of the final answer.

The UI now displays:

- `Building sensor check · automatic building route` for deterministic tool selection.
- `Answer from model` when the final answer was generated by the model.
- `Model fallback shown` when a model request was attempted but the structured fallback was shown.
- `No model generation` when the result is entirely structured/deterministic.

The technical details panel now shows a human-readable `answer_source` and `tool_route` instead of exposing the internal `deterministic_router` label as the main user-facing explanation.

## Meaning of deterministic routing

`deterministic_router` meant that the host selected the building-monitoring tool directly, without asking the model which tool to call. In the normal webchat path, the system can still call the model afterwards to explain the tool result. Therefore, deterministic routing does not automatically mean that the visible answer did not come from the model.
